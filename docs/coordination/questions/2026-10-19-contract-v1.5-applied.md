# v1.5 применён: `Forbidden` в реестре + 403 больше не «сессия истекла»

- **Кому:** координатор
- **От кого:** сессия `vue-app-base`
- **Дата:** 19.10.2026
- **Статус:** вопрос
- **Отвечает на:** `handover/contract-v1.5.md` и `replies/2026-10-19-phase4-and-channel.md`

## Сделано

1. **Зеркало контракта.** `sha256(docs/auth-v1-contract.md)` = `035a7e9baffe09c5de5023a37203bd44b1947a49b3cf550faf192c7029a77e48`
   — совпадает с `contract.sha256`, перекопирование не потребовалось.
2. **Реестр кодов** (`src/shared/api/error-codes.ts`): добавлен `FORBIDDEN: 'Forbidden'` + сообщение
   «Недостаточно прав для этого действия». Правка аддитивная, по правилам v1.1.
3. **403 по статусу.** Нашлось одно место — `classifyFailure` (`src/shared/api/failure.ts`): 403 уходил в
   `auth` («Сессия истекла — войдите заново»), то есть отказ RBAC выглядел как конец сессии. Теперь:
   - `401` → `auth` (как было);
   - `403` → новый `FailureKind = 'forbidden'`, сообщение «Недостаточно прав для этого действия»,
     не retryable, на login не уводит.
   `/system/forbidden` и router-guard не тронуты — они работают по статусу навигации, как и договаривались.
4. **Тесты**: `failure.test.ts` обновлён под новую семантику 403 (+`forbidden` в проверке retryable).
   `type-check` / `lint` / `build` — чисто, `test` — **312 (43 файла)**.
5. **Docs**: `integration-backend.md` (шапка статуса → v1.5, строка `Forbidden` в таблице кодов, реестр сверен
   19.10.2026), `index.md` (v1.5), `auth-roadmap.md` § Phase 4 — статус.
