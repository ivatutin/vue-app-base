## Сделано (3 правки из задания)

1. **Реестр** (`src/shared/api/error-codes.ts`): `PROFILE_NAME_INVALID: 'ProfileNameInvalid'` +
   сообщение «Проверьте имя: оно не должно быть пустым и не может содержать запрещённые символы».
   Зеркало контракта закоммичено: sha256 `d8a4b7b3…` = `contract.sha256` ✔ (v1.7).
2. **422 не retryable и текст по коду** — проверено тестом: `getErrorMessage` возвращает текст реестра,
   `isRetryableFailure(classifyFailure(err)) === false` (в `RETRYABLE` только offline/network/timeout/server).
   Поле в форме не очищается: `ProfilePage` показывает ошибку в `Alert`, значения остаются — пользователь правит
   введённое. Политику имён на клиенте **не дублировал** (набор запрещённых символов живёт в Keycloak).
3. **Тест**: `422 {"error":"ProfileNameInvalid"}` → сообщение реестра + не retryable. Тестов стало **328** (45 файлов).

## Живая проверка (важно: понадобилась пересборка образа)

Запущенный контейнер был собран **21.10 06:48**, то есть **до** `d61d06e` (batch-6): живой `PATCH` с
`firstName="<bad>"` возвращал прежний `503 ServiceUnavailable`. Пересобрал образ
(`docker compose build app` → `up -d app`, healthy за 2 с) и повторил:

```
PATCH /api/v1/users/me/profile {"firstName":"<bad>","lastName":"Name"}
→ 422 {"error":"ProfileNameInvalid","message":"Profile name is not accepted by the identity provider policy"}
PATCH … {"firstName":"User","lastName":"Dev"} → 200 (значение вернул)
```

То есть бэкенд-фикс работает, и в контейнере теперь честный 422. **Замечание:** после любых бэкенд-коммитов образ нужно
пересобирать — иначе стенд остаётся на старом коде (это уже второй раз ловится на приёмке).
