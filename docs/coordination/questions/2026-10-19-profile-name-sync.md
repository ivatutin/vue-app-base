# Имена из Keycloak не доходят до приложения: нужен sync на входе (или поля на регистрации)

- **Кому:** координатор
- **От кого:** сессия `vue-app-base`
- **Дата:** 19.10.2026
- **Статус:** вопрос
- **Источник:** живая проверка (регистрация `check-1019@example.test` → подтверждение письма → Keycloak → вход)

## Что увидел пользователь

После клика по ссылке подтверждения Keycloak запросил **имя и фамилию**. Пользователь ввёл их (`Test` / `Dev`),
подтвердил адрес, вошёл — а в приложении (`/account/profile`, шапка) имени нет.

## Факты (сверено с живым стендом и кодом, 19.10.2026)

1. **Keycloak**: у пользователя `firstName='Test'`, `lastName='Dev'`, `emailVerified=true`, `requiredActions=[]`.
2. **Почему Keycloak спросил**: в реалме `app` declarative user profile помечает
   `firstName`/`lastName` как `required: {"roles": ["user"]}` — каждому пользователю с ролью `user`
   профиль обязателен (Admin API `GET /admin/realms/app/users/profile`).
3. **Почему в приложении пусто**: shadow-БД приложения у того же пользователя содержит
   `first_name = null`, `last_name = null` (`user.users`, проверено запросом в Postgres).
4. **Почему не синхронизировалось**:
   - `sign-up/email` создаёт Keycloak-пользователя с `requiredActions: ['VERIFY_EMAIL']` и **без имён**
     (наша форма регистрации полей имени не имеет; в DTO контракта они есть как необязательные);
   - `ensureFromIdentity` кладёт в shadow-БД то, что пришло из sign-up, то есть `null`;
   - `OnUserSignedInHandler` при входе синхронизирует **только роли** (`on-user-signed-in.handler.ts:48-66`);
     дрейф email лишь логируется, `firstName`/`lastName` не синхронизируются вовсе.
5. Итог: имя есть в Keycloak и отсутствует в `/users/me`; при этом исправить его из приложения нельзя —
   `PATCH /users/:id/profile` админский (см. соседний вопрос `2026-10-19-self-profile-update.md`).

## Что предлагаю (нужно решение)

**A. Backend: синхронизировать профиль на входе.** В `OnUserSignedInHandler` (или отдельным
`EnsureProfileFromIdentity`) обновлять `firstName`/`lastName` из Keycloak, если они изменились, — так же,
как уже обновляются роли. Это закрывает и существующие аккаунты, и будущие правки имени на стороне Keycloak.
Дешёвая и симметричная правка: роли уже синхронизируются, профиль — нет.

**B. Frontend: поля «Имя»/«Фамилия» на регистрации (необязательные).** Контракт это позволяет
(`firstName?`/`lastName?` в теле `sign-up/email`, `max 100`). Тогда Keycloak получит имена сразу,
`UPDATE_PROFILE` после подтверждения не будет пустым, и shadow-БД заполнится на регистрации.
Минус — два лишних поля в форме; можно сделать их свёрнутыми («Указать имя», опционально).

**C. Realm: снять `required` для `user`.** Убирает лишний шаг в Keycloak, но не заполняет имена нигде —
это не решение проблемы, а её маскировка.

## Вопрос

1. Заводить **A** на бэкенде? (Я считаю это основным исправлением: источник истины — Keycloak.)
2. Делать **B** на фронте? Если да — в каком виде: два поля сразу или раскрывающийся блок «Указать имя (необязательно)»?
3. Пока A/B не сделаны, в отчётах фиксирую это как известное расхождение (не баг фронта): имя из Keycloak
   в приложении не отображается.
