# Вход «телефон + пароль»: сейчас невозможен — предложение на v1.7

- **Кому:** координатор
- **От кого:** сессия `vue-app-base`
- **Дата:** 20.10.2026
- **Статус:** отвечено
- **Источник:** вопрос владельца при ручной приёмке: «а можно войти по номеру телефона и паролю?»

## Факт (контракт v1.6, live)

| Метод | Тело | Результат |
|---|---|---|
| `POST /auth/sign-in` | `{ email, password }` | только email (DTO валидирует формат); телефон в поле email → `400 ZodValidationException` |
| `POST /auth/sign-in/phone` | `{ phone, verificationToken }` | только OTP/CIBA, пароль не участвует |

Следствие: у телефонного аккаунта пароль (например, после `POST /users/me/set-password`) нужен **только для `reauth`**
(смена пароля/контакта), но **не для входа** — войти можно лишь по OTP.

## Что нужно, чтобы появился вход «телефон + пароль»

1. **Бэкенд:** в password grant уходит Keycloak-username, а он по ADR-0017 — `usr_<hex>`; сейчас бэкенд резолвит
   его **по email** (`LOGIN_HANDLE_RESOLVER`). Нужно расширить резолвер: определять тип контакта (email/телефон) и
   искать `handle` по нормализованному номеру. Требование однозначности: у пользователя могут быть оба контакта —
   приоритет должен быть зафиксирован (предлагаю: сначала email, затем телефон; конфликт невозможен, т.к. оба
   контакта принадлежат одному shadow-пользователю).
2. **Контракт:** аддитивное расширение тела `sign-in` (`email` → `email?` + `phone?`, хотя бы одно) или отдельный
   `POST /auth/sign-in/phone/password`. Это **v1.7**; v1.6 заморожен.
3. **Фронт:** отдельная вкладка на `/auth/login` («Телефон и пароль») — не смешивать телефон с полем email
   (ровно эта ошибка сегодня дала `400`).

## Вопрос

1. Нужен ли вход «телефон + пароль» в v1.7? Если да — какая форма контракта предпочтительнее:
   расширить `sign-in` (`email` | `phone` в одном поле-дискриминаторе) или отдельный эндпоинт?
2. Пока v1.7 нет — фиксируем как ограничение: телефонный аккаунт входит только по OTP, пароль — для `reauth`.
