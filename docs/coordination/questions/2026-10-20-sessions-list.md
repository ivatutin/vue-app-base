# Список активных сессий: нужен эндпоинт (сейчас есть только «выйти везде»)

- **Кому:** координатор
- **От кого:** сессия `vue-app-base`
- **Дата:** 20.10.2026
- **Статус:** вопрос
- **Источник:** ручная валидация владельцем (шаг 15 чек-листа) — «Можно показать список текущих сессий, можно через отдельную модалку»

## Что есть сейчас

- `POST /users/me/logout-all` (v1.4) — гасит все сессии, тела нет, 204.
- **Эндпоинта со списком сессий нет**: в контроллерах бэкенда (`auth`, `user`) нет ни `GET /users/me/sessions`,
  ни чего-то про device-activity (проверено grep'ом по `*.controller.ts`).
- Keycloak умеет это нативно: Account Console → `/realms/app/account/#/device-activity` (там же logout конкретной сессии).

## Варианты (нужно решение)

**A. Эндпоинт `GET /users/me/sessions`** (предпочтительно, если делаем полноценно).
Бэкенд проксирует Keycloak Admin API `GET /admin/realms/{realm}/users/{id}/sessions`:
`[{ id, ipAddress, start, lastAccess, clients: { [clientId]: "…" }, browser? }]`.
Плюс, чтобы закрывать одну сессию: `DELETE /users/me/sessions/:id` (Keycloak `DELETE …/sessions/{sessionId}`).
Фронт: модалка «Активные сессии» в карточке «Сессии» — список (устройство/IP/последняя активность) + «Завершить» на каждой.

**B. Без нового контракта — ссылка на Account Console** (работает уже сегодня, но уводит из приложения).
Фронту нужен публичный URL Keycloak в конфиге (`VITE_KEYCLOAK_URL`, сейчас его нет), иначе в проде ссылка будет неверной.

**C. Ничего не делать** — только «выйти на всех устройствах».

## Вопрос

1. Делаем **A**? Тогда это контракт **v1.7** (аддитивно) и задание бэкенду; фронт готов сделать модалку сразу после сдачи.
2. Пока A не сдан — нужен ли **B** (ссылка в карточке «Сессии»)? Если да, скажите, откуда фронту брать URL Keycloak
   (env-переменная в `vue-app-base/.env` — единственный чистый способ).
