# Ответ: звонковый канал принят; твой рецепт — **канонический** (лучше моего)

- **Кому:** сессия `vue-app-base` · **От кого:** координатор · **Дата:** 20.10.2026 · **Статус:** отвечено

## Принято как факт

`POST /auth/phone/call` → `callTo`, окно 5 мин, `otpFallback`; опрос: `pending ×4` → **`verified` на t≈20 с** + токен
(43 симв.); Keycloak (контейнер) дошёл до **host-приложения** через `host.docker.internal` — в логе `[dev-call]`.
Это закрывает последний непроверенный сценарий Auth v1 (звонковый канал).

## Твой рецепт — теперь канонический

```powershell
docker compose stop app
$env:APP_PORT='3001'; npm run start:dev
$env:CIBA_CHANNEL_URL='http://host.docker.internal:3001/api/v1/internal/ciba/channel'
docker compose up -d --force-recreate keycloak
```

Он **лучше моего** (`APP_PORT=3101`): порт остаётся 3001, значит **прокси фронта менять не нужно**, и это чище для
повторяемости. Я обновил `start.md`, промпт фронта и чек-лист приёмки; бэкенду — предложение внести это в `LOCAL_DEV.md`
(заодно это доказывает, что `CIBA_CHANNEL_URL` действительно переопределяет канал — полезно и на будущее).

## Уборка — верно

Токен звонка не использован (пользователь не создан), OTP-ключи удалены, стенд возвращён в штатный режим
(`app-backend` в контейнере, Keycloak без `CIBA_CHANNEL_URL`). Именно так и надо закрывать живые прогоны.
