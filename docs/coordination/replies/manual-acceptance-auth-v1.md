> **Правило:** если шаг не прошёл — фиксируем «шаг N: ожидали X, получили Y» и не идём дальше этого блока.

## 0. Подготовка стенда

```powershell
# 1. инфраструктура (почта Keycloak — в Mailpit; контейнер app пока не нужен)
cd C:\WORK\v1m\njs-server
docker compose up -d postgres redis keycloak mailpit

# 2. приложение с хоста (dev-заглушки: письма/коды в логе) — тот же порт 3001
docker compose stop app
$env:APP_PORT='3001'; npm run start:dev

# 3. для ЗВОНКОВОГО канала — перенаправить CIBA на host-приложение
$env:CIBA_CHANNEL_URL='http://host.docker.internal:3001/api/v1/internal/ciba/channel'
docker compose up -d --force-recreate keycloak

# 4. фронт (прокси /api → 3001 уже настроен)
cd C:\WORK\v1m\vue-app-base
npm run dev
```

- **Без шага 3** телефонный вход/регистрация упадут с `503`: CIBA-канал по умолчанию смотрит в контейнер
  (`docker-compose.yml:85`), а dev-провайдер звонка живёт только в host-приложении.
- Шаги 2–3 проверены живьём 20.10 (звонок → `verified` через ~20 с, CIBA доходит до host).
- Возврат в штатный режим: `docker compose up -d --force-recreate keycloak` (без переменной) + поднять `app`.

- Mailpit (письма Keycloak): **http://localhost:8025**
- Письма/коды **смены контакта** — в **логе бэкенда**: `[dev-email] … code=NNNNNN`, `[dev-sms] … code=NNNNNN`
- SMS-коды регистрации/входа — тоже в логе (`[dev-sms]`)
- Тестовые адреса: свои (`you+test1@…`), номера — `+799900000NN`

## 1. Email-регистрация и подтверждение

1. `/auth/register` → таб «E-mail» → email + пароль + галочка условий → «Создать».
   **Ждём:** экран «проверьте почту», адрес замаскирован.
2. Mailpit: письмо «Verify email» → ссылка ведёт на **Keycloak** (это ожидаемо).
3. Клик по ссылке → Keycloak подтверждает email → вернуться на сайт → **войти**.
   **Ждём:** вход успешен, `status = active`.

## 2. Вход и восстановление пароля

4. Выход → вход тем же паролем. **Ждём:** вход.
5. «Забыли пароль?» → email → письмо «Update Your Account» → ссылка → задать новый пароль в Keycloak → вход новым.
   **Ждём:** старый пароль не работает, новый — работает.

## 3. Телефон: регистрация, вход, код и обратный звонок

6. `/auth/register` → таб «Телефон» → номер → «Получить код» → код из лога → подтвердить.
   **Ждём:** аккаунт `active`, `phoneVerified: true`.
7. Выход → `/auth/login` → таб «Телефон» → код → вход. **Ждём:** вход.
8. Обратный звонок: на шаге кода выбрать «Позвонить вместо кода» → видим `callTo` и таймер → **не звонить**,
   дождаться dev-подтверждения (~15 с). **Ждём:** статус `verified`, вход проходит без ввода кода.

## 4. Профиль и пароль

9. `/account/profile`: изменить имя → сохранить → перезагрузить страницу. **Ждём:** имя сохранилось.
10. `/account/security`: «Сменить пароль» (нужен текущий) → войти новым.
11. Passwordless-пользователь (телефонный): «Задать пароль» → OTP на телефон → пароль установлен → вход по паролю.

## 5. Смена контакта (двойной OTP) — самый важный блок

12. `/account/security` → «Контакт» → сменить email:
    - если контакт **подтверждён** — приходят **два** кода: на старый и на новый (оба в логе/на почте);
    - если **не подтверждён** — только на новый.
    **Ждём:** после успеха сессия **отозвана** → уводит на вход; вход проходит с **новым** контактом.
13. Негатив: попытаться сменить на **занятый** email. **Ждём:** понятная ошибка (409), сессия жива.
14. Отмена: «Отменить смену» → затем сразу новый запрос. **Ждём:** второй запрос проходит (не «висит» предыдущий).

## 6. «Выйти на всех устройствах»

15. Войти в **двух** браузерах/профилях. В одном нажать «Выйти на всех устройствах».
    **Ждём:** оба разлогинены; в старом токене любой запрос → `401`; новый вход работает (локута нет).

## 7. RBAC

16. `user-dev` → открыть админский маршрут (например `/users`) → **ждём** `/system/forbidden`.
17. `admin-dev` → тот же маршрут → **ждём** доступ.
    (пароли dev-аккаунтов — в `handover/dev-accounts-and-stand.md` координации)
