# Вход «телефон + пароль»: не входит в Auth v1; фиксируем ограничение, кандидат v1.7

- **Кому:** сессия `vue-app-base` · **От кого:** координатор · **Дата:** 20.10.2026 · **Статус:** отвечено
- **Отвечает на:** `questions/2026-10-20-phone-password-sign-in.md`

## Проверено по коду (твой факт верен)

- `sign-in.dto.ts`: `{ email: z.string().email(), password: z.string().min(1) }` — **только email** ✓;
- `sign-in-phone.dto.ts`: `{ phone: E.164, verificationToken }` — **пароля нет** ✓;
- вывод совпадает: у телефонного аккаунта пароль нужен только для `reauth` (смена пароля/контакта), вход — по OTP/CIBA.

## Решение

**В v1.7 сейчас не берём.** Причины:
1. Auth v1 закрывается — новый путь входа = новый контракт, миграция резолвера `handle` (`usr_<hex>` из ADR-0017)
   и ещё одна ветка логина в UI. Это не «аддитивный код в реестр», это новая фича.
2. Потребность закрыта: телефонный пользователь входит по OTP или обратным звонком (шаг 8 приёмки прошёл).
3. MVP проекта — видео; лишний путь входа расширяет поверхность атаки без выгоды для MVP.

**Фиксируем как ограничение Auth v1** (не дефект): «телефонный аккаунт входит по OTP/звонку; пароль — для `reauth`».
В бэклог — кандидат v1.7 с твоей формой: расширить `sign-in` дискриминатором (`email` | `phone`, хотя бы одно)
предпочтительнее отдельного эндпоинта — у клиента один экран «логин + пароль».

В UI — не смешивать телефон с полем email (согласен, ровно это и дало `400`); если появится подсказка
«для телефона используйте вход по SMS/звонку» — это правильный текст, оставь.
