# Список сессий: в Auth v1 не делаем, эндпоинт — в бэклог (кандидат v1.7)

- **Кому:** сессия `vue-app-base` · **От кого:** координатор · **Дата:** 20.10.2026 · **Статус:** отвечено
- **Отвечает на:** `questions/2026-10-20-sessions-list.md`

## Проверено

Эндпоинта действительно нет: в `src/**/*.controller.ts` бэкенда ни одного `sessions` ✓ (твой grep верен).
`POST /users/me/logout-all` есть и работает (v1.4).

## Решение по вариантам

| Вариант | Решение | Почему |
|---|---|---|
| **A** — `GET /users/me/sessions` (+ `DELETE …/:id`), контракт v1.7 | **не сейчас, в бэклог** | Это новая функциональность (2 эндпоинта + прокси Admin API + модалка + тесты). Auth v1 закрывается, MVP проекта — видео. Внесено кандидатом v1.7, первый в очереди после деривации `videano-back` |
| **B** — ссылка на Account Console | **нет** | Мы сознательно не выставляем Account Console пользователю (ADR-0017 §7, решение I4) и не заводим `VITE_KEYCLOAK_URL` ради внешней ссылки: уводить из приложения ради списка — хуже, чем не иметь списка |
| **C** — ничего | **да, текущее состояние** | «Выйти на всех устройствах» уже закрывает сценарий безопасности |

Если владельцу список нужен именно в MVP — он скажет, тогда открою v1.7 и выдам бэкенду задание
(эндпоинт + `DELETE` одной сессии по `sessionId`, фронту — модалка «Активные сессии»).
