# `/inbox` — входящие фронт-сессии в дереве координатора

Ты — исполнитель фронт-части Auth v1 в репозитории `C:\WORK\v1m\vue-app-base`. Координатор ведёт общее дерево
`c:\vim\prj\video-service\docs` и переписывается с тобой **только файлами**. Этот skill — твой «входящий ящик»:
он ничего не решает сам, а собирает факты и показывает, что от тебя требуется.

## Границы (жёсткие)

- **Читать можно всё** дерево координатора.
- **Писать только** в `docs/auth/sessions/vue-app-base/questions/` — новый файл на каждый новый вопрос/отчёт.
- Файл в `questions/` после создания **заморожен**: не редактировать, не переименовывать; статус в нём ставит координатор.
  Ответы координатора (`replies/`, `reviews/`, `handover/`) — тоже **только чтение**.
- `docs/auth-v1-contract.md` в репозитории — **производный файл**: руками не правится, только перекопируется целиком
  при расхождении sha256. Изменение контракта — только через координатора (стоп + вопрос).
- Если разошлись доки и бэкенд — **истина у бэкенда** (`C:\WORK\v1m\njs-server`), доки правим по факту.

## Алгоритм

1. **Доступ.** Проверь, что корень сессии существует. Нет — сообщи одной строкой («дерево координатора недоступно по
   пути X») и заверши работу, ничего не выдумывая.
2. **Состояние.** Прочитай `.claude/inbox-state.json`. Если файла нет — это первый прогон: тогда «новым» считается всё
   содержимое, но в отчёте подавай это как базовый срез, а не как срочные входящие.
3. **Сканирование.** Собери список файлов (path, size, mtime, sha256) по путям из таблицы выше.
4. **Классификация:** `NEW` (нет в состоянии) · `CHANGED` (есть, но mtime/размер другие) · `GONE` (был, файла больше нет).
   `questions/` в «новое» не попадает (это твои же файлы) — по ним считается **статус** (шаг 6).
5. **Зеркало контракта.** `sha256(docs/auth-v1-contract.md)` против содержимого `…\docs\auth\contract.sha256`.
   - Совпало → «✔ зеркало актуально».
   - Не совпало → **разрешено перекопировать** `contract.md` в `docs/auth-v1-contract.md` целиком (это синхронизация
     производного файла, а не правка контракта), затем повторить сверку. Не сошлось и после копирования — сообщи
     координатору (регенерирован ли `contract.sha256`?).
6. **Вопросы ↔ ответы.** Для каждого файла в `questions/` ищи парный файл в `replies/` **по имени**; дополнительно —
   упоминание имени файла вопроса в тексте ответов (координатор иногда отвечает одним файлом на несколько). Выпиши из
   ответа строку `Статус:` (`отвечено` / `принято`) и требования к сессии. Ответы без пары — «прочие входящие»
   (например, первый `replies/initial-scope.md` — постановка, а не ответ). Для статуса `отвечено` проверь по репозиторию
   (`grep` по `docs/` и `src/`, `git log`), **применены ли** правки: не применены → в 🔴.
7. **Доска и журнал.** Из `status.md` вытяни строки «Доска фаз Auth v1» со `Frontend` ≠ ✅; непустые строки
   «Расхождения с контрактом»; последние записи журнала, где упомянуты `vue-app-base`, `/inbox` или «фронт». Запись про
   наш репозиторий в «Расхождениях» — всегда 🔴.
8. **Не отработанные материалы.** Для каждого файла из `handover/` проверь, упоминается ли он в нашем репозитории
   (`grep` по `docs/`). Не упоминается → «материал не отработан в доке/коде».
9. **Состояние (обновление).** Запиши новый `.claude/inbox-state.json`: `checkedAt`, хэши/размеры/mtime файлов, статусы
   вопросов, sha256 канонического контракта и зеркала. Обновляй **всегда**, даже если новых файлов нет.
10. **Отчёт** — строго в формате ниже. В дереве координатора и в репозитории ничего не меняй без подтверждения
    пользователя (исключение — перекопирование зеркала из шага 5: оно разрешено протоколом).

## Формат отчёта

```
# /inbox — <дата время>

## 🔴 Требуют действия
- <путь или тема> — <факт> → <что сделать>   (напр.: «replies/X.md помечен `отвечено`, но правки не применены → обновить docs/…»)

## 🟡 Важно знать
- <что изменилось в задании/доске/статусе> → <следствие>

## 🟢 Новое к сведению
- <файл> — <одна строка о содержании>

## ✅ Проверки
- зеркало контракта: sha256 <…> = канонический ✔ (или ⚠ + что сделал)
- вопросы: N открыто · M отвечено · K принято
- материалы: X в handover, из них Y не отработаны
- ревью: <сколько файлов, вердикт одной строкой>

## Итого
<новых файлов: N · изменённых: M · ответов: X · открытых вопросов: Y>
Обновить состояние и применить правки по ответам? (да / выбрать пункты / нет)
```

Последняя строка отчёта: «состояние: `.claude/inbox-state.json`». Если ответ требует работы — следующим шагом правки
применяются, а координатору по факту отправляется **новый** файл в `questions/` (статусы `вопрос → отвечено → принято`
ставит только он).

## Что не делать

- Не пересказывать весь `status.md` — только релевантное нашему репозиторию.
- Не считать отсутствие ответа ошибкой: у координатора свой темп, открытые вопросы просто перечисляются.
- Не додумывать решения координатора и не править контракт/реестр кодов по своей инициативе.
- Не удалять и не переписывать файлы в дереве координатора (в т.ч. свои `questions/` — история решений часть ценности).
